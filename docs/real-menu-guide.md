# دليل القائمة الحقيقية — Real Menu

هذا الدليل خاص بـ **تحميل قائمة المحل الحقيقية** قبل الإطلاق (التشغيل الفعلي).
نظام CI يستمر باستخدام بيانات **التجربة (demo)** فقط؛ القائمة الحقيقية تُحمَّل
مرة واحدة عبر سكربت الاستيراد.

- ملف البيانات المجهّز: `docs/real-menu.json`
- القالب القابل للتعبئة: `docs/real-menu-template.json` (انسخه ثم املأه)
- مجلد صور المنتجات: `public/menu/`
- سكربت الاستيراد: `scripts/ingest-real-menu.ts`

---

## 1) ما الذي يفعله الاستيراد

`ingest-real-menu.ts` **يستبدل** كتالوج التجربة بالكامل (المنتجات، الفئات،
المعدِّلات، الوصفات) من ملف `real-menu.json`، مع **الحفاظ** على:

- الموظفين (`staff`) والصلاحيات،
- الإعدادات (`settings`) بما فيها العلامات والتـعلم والفاتورة،
- الطاولات ورموز QR (`tables`)،
- سجلّ الطلبات السابقة (`orders`) — قراءة التاريخ تبقى سليمة لأن
  `order_items` تحفظ لقطة من الأسماء والأسعار.

السكربت **مُعاملاتي (transactional) وأيديمبوتنت**:

- كل شيء يكتب داخل معاملة واحدة؛ أي خطأ في أي منتج يمنع **التزام** أي تغيير
  وتُعرض رسالة تُحدد المشكلة بالضبط.
- تشغيله مرتين على البيانات نفسها يعيد نفس النتيجة دون مضاعفة.

## 2) بنية الملف (شرح الحقول)

```jsonc
{
  "branch": { "slug": "qalqilya", "name_ar": "أياسوفيا — قلبيلية" },
  "ingredients":   [ ... ],
  "categories":    [ ... ],
  "products":      [ ... ],
  "tables":        [ ... ]
}
```

### الفرع `branch`

| الحقل     | الوصف                                                                                              |
| --------- | -------------------------------------------------------------------------------------------------- |
| `slug`    | معرف الرابط القصير، بحروف لاتينية صغيرة وشرطات (مثل `qalqilya`). يُنشأ تلقائيًا إن لم يكن موجودًا. |
| `name_ar` | اسم الفرع للعرض.                                                                                   |

### الخامات `ingredients[]`

| الحقل          | الوصف                                         |
| -------------- | --------------------------------------------- |
| `name_ar`      | اسم الخامة. يجب أن يكون فريدًا.               |
| `unit`         | الوحدة: `ml` أو `g` أو `piece`.               |
| `currentStock` | الرصيد الحالي.                                |
| `reorderAt`    | حدّ إعادة الطلب (يضبط تنبيه المخزون المنخفض). |

### الفئات `categories[]`

| الحقل     | الوصف                                                                   |
| --------- | ----------------------------------------------------------------------- |
| `key`     | مفتاح فريد (لاتيني، مثل `bubble_tea`). تُستخدمه المنتجات للإشارة للفئة. |
| `name_ar` | اسم الفئة المعروض.                                                      |
| `sort`    | ترتيب العرض (الأصغر أولًا).                                             |

### المنتجات `products[]`

| الحقل              | الوصف                                                                                |
| ------------------ | ------------------------------------------------------------------------------------ |
| `name_ar`          | اسم المنتج المعروض. **يجب أن يكون فريدًا.**                                          |
| `desc_ar`          | سطر وصف قصير (اختياري).                                                              |
| `priceILS`         | السعر بالشيكل، **أكبر من صفر** (يتحوّل لآحاد/أغوروت داخل السكربت).                   |
| `category`         | `key` الفئة التي ينتمي إليها المنتج.                                                 |
| `imageFile`        | اسم ملف الصورة داخل `public/menu/` (مثل `milk-tea-classic.jpg`). يجب أن يوجِد الملف. |
| `modifierGroups[]` | مجموعات المعدِّلات (انظر أدناه).                                                     |
| `recipe[]`         | وصفة المنتج: قائمة خامات برمز `ingredient` (اسم خامة موجود) و`qty` (الكمية).         |

#### مجموعة معدِّلات `modifierGroups[]`

| الحقل       | الوصف                                                                       |
| ----------- | --------------------------------------------------------------------------- |
| `type`      | `single` (اختيار واحد) أو `multi` (متعدد).                                  |
| `name_ar`   | اسم المجموعة (مثل "الحجم"، "نوع الحليب").                                   |
| `required`  | هل المجموعة إلزامية؟ `true`/`false`.                                        |
| `max`       | للمجموعة `multi` فقط: الحد الأقصى لعدد الخيارات (اختياري؛ `null` = بلا حد). |
| `options[]` | قائمة الخيارات.                                                             |

#### خيار معدِّل `options[]`

| الحقل           | الوصف                                                                                                                        |
| --------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `name_ar`       | اسم الخيار.                                                                                                                  |
| `deltaILS`      | زيادة/خصم السعر بالشيكل (اختياري، افتراضيّ `0`).                                                                             |
| `ingredientQty` | إذا كان الخيار يستهلك مخزونًا: كائن `{ "ingredient": "<اسم الخامة>", "qty": <الكمية> }`. انظر **قاعدة عدم التكرار** بالأسفل. |

#### وصفة `recipe[]`

```jsonc
{ "ingredient": "شاي أسود مركز", "qty": 200 }
```

`ingredient` اسم خامة موجود في قائمة `ingredients`، و`qty` الكمية المستهلكة من هذه
الخامة لكل مبيعة من المنتج.

### الطاولات `tables[]`

```jsonc
{ "code": "T1" }
```

رمز الطاولة. تُضاف فقط لو لم تكن موجودة (تُحافظ على رموز QR القائمة).

## 3) ⚠️ قاعدة عدم التكرار (الأهم — لا تخالفها)

قاعدة المخزون (§8.4): **لا يمكن أن تكون الخامة نفسها في وصفة المنتج** **و** **مربوطة
بخيار معدِّل** من نفس المنتج. لو حدث ذلك، سَتُخصَم مرتين في مبيعة واحدة.

- الخامة التي تُعدّ جزءًا بسيطًا من الوصفة (مثل الشاي/الحليب في المقادير) → تذهب
  في `recipe` فقط.
- الخامة "القابلة للتبديل"/الإضافة التي يستهلكها خيار معيّن (مثل حليب الشوفان، لؤلؤ
  التابيوكا) → تذهب في `ingredientQty` لخيار معدِّل فقط، **ويشترط** أن تكون
  مجموعتها `type: "single"` و`required: true`.
- لا تكرار مطلقًا بين `recipe` و `ingredientQty` لنفس المنتج.

> السكربت **يُفشل ويتراجع عن التزام شيء** إذا وجد أي تكرار أو خيارًا مربوطًا
> بخامة في مجموعة غير `single` وإلزامية.

**مثال صحيح** (حليب الشوفان في خيار فقط، والحليب الطازج في الوصفة فقط):

```jsonc
"modifierGroups": [
  {
    "type": "single", "name_ar": "نوع الحليب", "required": true, "max": null,
    "options": [
      { "name_ar": "حليب طازج", "deltaILS": 0 },
      { "name_ar": "حليب شوفان", "deltaILS": 1,
        "ingredientQty": { "ingredient": "حليب شوفان", "qty": 100 } }
    ]
  }
],
"recipe": [
  { "ingredient": "حليب طازج", "qty": 100 }
]
```

## 4) التحقق قبل الالتزام (يعمل تلقائيًا)

- كل الأسعار (`priceILS`) > 0، وتُحوَّل إلى أغوروت (بلا أعداد عائمة).
- `name_ar` للمنتج والصنف فريدان؛ الفئة/الخامة المشار إليها موجودة.
- ملفات الصور موجودة فعليًا في `public/menu/`.
- أسماء الخامات فريدة، والوحدات ضمن `ml / g / piece`.
- لا تكرار بين الوصفة والربط (قاعدة §3)، ومجموعات الربط `single`+`required`.
- لو وُجد أي مخالفة: لا يُلتزم أي تغيير، ويُطبع ملخص بالأخطاء.

## 5) التشغيل

```bash
# 1) ضع الصور في:   public/menu/
# 2) املأ ملف البيانات:   docs/real-menu.json   (انسخ القالب أولًا)

# 3) نفّذ الاستيراد (يقرأ docs/real-menu.json افتراضيًا، أو حدد المسار):
npx tsx scripts/ingest-real-menu.ts
npx tsx scripts/ingest-real-menu.ts docs/real-menu.json

# 4) تأكد من أن اختبارات المخزون ترى القائمة الحقيقية:
npx vitest run __tests__/seed-stock-semantics.test.ts
# ثم كل الاختبارات:
npx vitest run
```

عند النجاح يُطبع ملخص: عدد الخامات/الفئات/المنتجات/المجموعات/الخيارات/الوصفات،
وعدد الطاولات، وعدد عناصر التجربة التي أُزيلت.

---

## 6) ملاحظات

- **CI لا يقرأ `real-menu.json`**: CI يُبني ويختبر دائمًا على بيانات التجربة
  (`db:seed`). الملف الحقيقي محليّ للتحضير فقط؛ إن أردت استبعاده من الإعادة ضِفه
  إلى `.gitignore` قبل ملئه بالبيانات الفعلية.
- **الطلب**: دقيق الحد؟ طبّق الإزالة عبر السكربت مباشرة («REPLACES demo»).
- إذا كانت هناك طلبات **حقيقية** مخزّنة بالفعل، احرص على نسخة احتياطية أولًا؛
  السكربت يحافظ على `orders` لكن المشروع/المخزون يُبنى من جديد من ملفك.
