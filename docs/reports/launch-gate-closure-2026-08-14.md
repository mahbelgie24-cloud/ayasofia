## 2. Owner Decision Requests

### DR-1 — نسبة ضريبة القيمة المضافة (P0-1)

- **السؤال:** ما نسبة ضريبة القيمة المضافة الرسمية المطبقة على المبيعات؟
- **الخيارات:** نسبة محددة (مثال 17%) / صفر (إعفاء) / أخرى.
- **الأثر:** كل بيع حالياً بلا ضريبة → أثر مالي مباشر على التقارير والإيصالات.
- **التوصية الفنية:** تأكيد النسبة مع محاسب محلي (spec §15)، ثم تعيينها.
- **الحقل:** `tax_rate` = `___` (نسبة مئوية، مثال `"17"`).

### DR-2 — العملة (P0-2)

- **السؤال:** هل العملة الرسمية للمبيعات هي الشيكل (₪ ILS)؟
- **الخيارات:** ILS (مُعيّن حالياً) / عملة أخرى.
- **الأثر:** كل الحسابات بوحدات أغورة ILS؛ تغيير العملة يتطلب مراجعة عرض الأسعار.
- **التوصية الفنية:** ILS (افتراض spec §15) — تأكيد فقط.
- **الحقل:** `currency` = `___` (القيمة الحالية `ILS`).

### DR-3 — القائمة الحقيقية (P0-3)

- **السؤال:** هل القائمة الحقيقية (منتجات/أسعار/وصفات/معدّلات) جاهزة للتعبئة؟
- **الخيارات:** تعبئة `docs/real-menu-template.json` → `docs/real-menu.json` / تأجيل.
- **الأثر:** النظام يعمل حالياً ببيانات demo (23 منتجاً)؛ لا يمكن البيع الفعلي بدونها.
- **التوصية الفنية:** تعبئة القالب ثم تشغيل `scripts/ingest-real-menu.ts` (مع نسخ احتياطي G3).
- **الحقل:** ملف `docs/real-menu.json` مكتمل.

### DR-4 — عزل البيئات (P0-4)

- **السؤال:** هل يمكن توفير مشروع Supabase منفصل للـ staging/الإنتاج؟
- **الخيارات:** مشروع staging جديد (مجاني/hobby) / إبقاء مشترك (غير موصى به).
- **الأثر:** يمنع تلوث بيانات الإنتاج ببيانات الاختبار، ويسمح بـ e2e معزولاً.
- **التوصية الفنية:** مشروع staging + أسرار `STAGING_*` في GitHub (مُعرّفة في `e2e.yml`).
- **الحقل:** `STAGING_SUPABASE_URL` / `STAGING_DATABASE_URL` / مفاتيح.

### DR-5 — التشغيل الموازي (P0-5)

- **السؤال:** متى يبدأ التشغيل الموازي أسبوعياً بجانب العملية اليدوية؟
- **الخيارات:** تاريخ بدء / مدة.
- **الأثر:** شرط إلزامي من spec §13 قبل القطع الكامل.
- **التوصية الفنية:** أسبوع موازٍ كامل، مقارنة Z-report بالعد اليدوي يومياً.
- **الحقل:** تاريخ البدء + مدة الموازاة.
