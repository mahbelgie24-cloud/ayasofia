## قاعدة النطاق الواحد (Single Scope Rule)

> **لا تنفذ أكثر من ميزة واحدة في جلسة تطوير واحدة.**

هذا هو أهم حد في المشروع. أي وكيل AI يتجاوز هذا الحد يُعتبر مُخطئًا — حتى لو بدا أن الميزة التالية "سهلة" أو "مرتبطة".

**سبب القاعدة:** منع الفوضى، تسهيل المراجعة، ضمان أن كل ميزة مكتملة ومُختبرة قبل الانتقال للتالية.

**مصدر القاعدة:** `AGENTS.md` (سطر: "Work on one roadmap phase item at a time").

## حدود التصميم (Design Constraints)

| الحد                      | التفصيل                          | المرجع    |
| ------------------------- | -------------------------------- | --------- |
| Modular Monolith فقط      | لا microservices، لا توزيع       | spec §4   |
| Single-branch shop        | لا multi-tenancy في v1           | spec §9   |
| Integer minor units للمال | لا float في حسابات الأسعار أبدًا | AGENTS.md |
| RTL أساسي                 | العربية هي اللغة الأولى للواجهة  | spec §6   |
| PIN 4 أرقام               | لا Email/Password للموظفين       | spec §8.1 |

## حدود البيانات (Data Constraints)

| الحد                       | التفصيل                                      |
| -------------------------- | -------------------------------------------- |
| **لا تخزين للـ PIN الخام** | `pin_hash` فقط (scrypt + salt)               |
| **لا Secrets في الكود**    | كل المفاتيح في `.env.local` (مُستثنى من git) |
| **لا أسعار من العميل**     | السعر النهائي دائمًا من الخادم               |
| **لا حذف للطلبات**         | الأوامر تُلغى (status=cancelled) ولا تُحذف   |
| **كل حركة مخزون مُسجلة**   | `inventory_moves` مع reason + مرجع           |

## حدود الكود (Code Boundaries)

| القيد                                           | ممنوع | مسموح                            |
| ----------------------------------------------- | ----- | -------------------------------- |
| استيراد `pricing-server.ts` في Client Component | ❌    | ✅ فقط في Server Actions/RSCs    |
| استيراد `service.ts` في Client Component        | ❌    | ✅ فقط في Server Actions         |
| `parseFloat` على أسعار من Drizzle               | ❌    | ✅ `toMinorUnits` أو تحويل نصي   |
| تعديل مباشر للـ DB دون Drizzle                  | ❌    | ✅ عبر Drizzle ORM فقط           |
| تخطي RLS                                        | ❌    | ✅ عبر service client فقط + مبرر |

## حدود الجودة (Quality Gates — Go/No-Go)

قبل أن تنتقل أي ميزة من `in_progress` إلى `completed`:

- [ ] TypeScript: 0 أخطاء (`tsc --noEmit`)
- [ ] ESLint: 0 أخطاء (التحذيرات مسموحة إذا كانت مبررة)
- [ ] الاختبارات: كلها ناجحة (`vitest run`)
- [ ] لا تدهور في التغطية (لا حذف اختبارات دون بديل)
- [ ] كل server action جديد يبدأ بـ `requireStaffSession` (إن تطلب)
- [ ] كل مسار كتابة يمرر `idempotencyKey`
- [ ] لا `parseFloat` مباشر على أسعار/مخزون
- [ ] المراجعة البشرية أو مراجعة Sonnet موثقة
